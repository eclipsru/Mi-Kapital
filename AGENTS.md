# Правило выпусков и обновлений

После каждого изменения приложения обеспечивайте доступность новой версии через обновления для Windows и Android, а не только запись изменений в Git. Дождитесь завершения GitHub Actions, проверьте опубликованный выпуск, версию, манифест, установщик Windows и подписанный APK Android; если сборка или публикация не удалась, исправьте причину либо явно сообщите пользователю, что обновление ещё недоступно. Проверки и сохранность данных пропускать нельзя. Не обещайте публикацию до её подтверждения.

При изменении Android-оболочки увеличивайте `android/shell-version.json`, чтобы старые установки предложили новый подписанный APK; используйте тот же ключ подписи. При изменении Electron-оболочки убедитесь, что работает обновление установщиком. Проверяйте обратную совместимость и путь обновления с уже опубликованных версий; при необходимости объясните пользователю безопасный способ перехода без удаления данных.

# Рабочий журнал

Перед началом работы просматривайте `WORKLOG.md` и актуальное состояние файлов. После каждого существенного изменения дополняйте журнал краткой датированной записью: что изменено, что проверено, что осталось и подтверждён ли выпуск. Если позднее появится подтверждённый результат, обновляйте запись. Не фиксируйте в журнале персональные финансовые данные, пароли, секреты, ключи сопряжения, QR-коды или содержимое резервных копий. Не заменяйте проверку репозитория и тестов утверждениями из журнала.
