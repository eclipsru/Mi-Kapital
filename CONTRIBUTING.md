# Правило публикации изменений

Изменения приложения считаются опубликованными только после появления новой стабильной версии в GitHub Releases. Не сообщайте пользователю, что приложение обновлено, если изменён только код в рабочей копии или ветке.

Для завершённого изменения:

1. Запустить `npm test` и `npm run build` и устранить ошибки.
2. Зафиксировать изменения и отправить коммит в рабочую ветку репозитория. Ветки `main` и `arena/**` запускают Windows workflow; он собирает приложение, проверяет обычное и дифференциальное обновление на Windows и автоматически публикует новый релиз только после успешных проверок.
3. Дождаться завершения GitHub Actions. Проверить, что опубликованная версия является последним релизом и содержит необходимые файлы обновлятора (`update-manifest.json`, `update-*.gz`, `latest.yml` и установщик). Android workflow собирает APK и прикрепляет его к релизу, если доступна конфигурация подписи.
4. Только после проверки релиза сообщить пользователю, что новая версия доступна через обновлятор. Если workflow или публикация не удались, объяснить, что именно не прошло, и не заявлять об успешной публикации.

Не создавайте релиз вручную в обход workflow: релиз должен пройти автоматические проверки сборки, сохранности данных и обоих путей обновления.
