# Мой капитал

Локальное приложение для Windows 10/11 x64. Четыре раздела: **Мой капитал**, **Доходы**, **Долги**, **Расчёт**. Тёмное оформление и оранжевый акцент взяты из дизайн-системы сайта `eclipsru/Arenda-Nvk`.

## Скачать

**[Последняя проверенная версия для Windows](https://github.com/eclipsru/Mi-Kapital/releases/latest)**

На Windows скачайте `Mi-Kapital-Setup-2.0.x.exe`, на Android — `Mi-Kapital-mobile.apk`. Устанавливайте обновление Android поверх старой версии, не удаляя приложение и его данные; перед обновлением рекомендуется экспортировать резервную копию. После первой установки новые версии доступны через кнопку **«Обновления»** в самом приложении. Сборка не имеет коммерческой Authenticode-подписи, поэтому Windows SmartScreen может показать предупреждение.

## Как учитываются деньги

- **«Общий капитал»** = **активы + остаток без долгов**. Долги в нём не учитываются вообще: ни новые, ни старые, ни погашенные — ни получение займа, ни платёж его не меняют. Покупка товара не уменьшает общий капитал: она переводит сумму из остатка в активы. Продажа возвращает тело покупки в остаток и добавляет 15% чистой прибыли в капитал.
- **«Остаток»** на главной — капитал вне товаров без движений по долгам. Он считается по денежным счетам без полной выручки шабашек, но с 15% их чистой прибыли. Фактические остатки отдельных счетов по-прежнему учитывают движение денег по долгам. Обычные расходы, корректировки и прежние поступления остаются в расчёте. Пример: старт 200 ₽, покупка за 200 ₽ → остаток 0 ₽ и активы 200 ₽; продажа за 500 ₽ с прибылью 300 ₽ → остаток 245 ₽; шабашка 1000 ₽ → +150 ₽, итог 395 ₽.
- **«Активы»** — собственные деньги, вложенные в непроданные товары, без справочной суммы инвестора. На странице «Перепродажи» сводка непроданных товаров показывает вложения **включая** деньги инвестора.
- **«Мои счета»** — три карточки ролей: **Капитал · 15%**, **На руки · 70%**, **На долги · 15%**. Роль назначается вручную существующему счёту. Карточка показывает начисленную долю чистой прибыли и **ничего не вычитает**. Остальные счета без роли показывают денежный остаток отдельно.
- **«Доходы»** считает только **чистую прибыль**: перепродажи — цена продажи минус цена покупки и доля инвестора; шабашки — полученная сумма минус расходы на работу. Распределение 15/15/70 начисляется на карточки ролей в «Моём капитале».
- **«Перепродажи»**: сводка сверху, ниже «Добавить товар», вкладки **Все товары / В наличии / На подготовке / На продажи / Продано**. Карточки компактные, по три в ряд на широком экране; показывают состояние, время в каждом состоянии, чистую прибыль и кнопку **«Вложения»**.
- Форма товара: фото (до 4), вид, дата покупки, состояние, источники **«Капитал»** и **«Карман»** без выбора счёта (счёт подставляется по роли), описание и голосовая заметка. Сумма «Из кармана» не списывается со счёта и при покупке не попадает в остаток; она входит в активы и цену покупки. При продаже цена покупки и 15% чистой прибыли попадают в остаток. Инвестор выбирается из списка людей раздела **«Долги»**; условие — **% от чистой прибыли**. Сумма инвестора справочная, отдельное поступление не создаётся.
- При продаже на счёт возвращаются **цена покупки + 15% чистой прибыли** в капитал. Доли 70% на руки и 15% на долги начисляются на карточки ролей. При убытке возвращается цена продажи, убыток уменьшает остаток; чистая прибыль отрицательная, распределение нулевое. Продажу можно изменить или отменить, товар — удалить; суммы пересчитываются без задвоения.
- **«Шабашки»**: тот же статистический блок, что и в «Доходах» — чистая прибыль за период и динамика. Вкладки **«Выполнено»** / **«Запланировать»**. В выполненной форме первое поле — вид работы, дальше поля вида, полученная сумма и расходы. План не меняет деньги.
- **«Долги»**: список, а не карточки. Справа вверху — фильтр по людям с вариантом **«Все»**, круглая кнопка **«+»** добавляет человека с одним полем «Имя». Сводка содержит кнопку **«Отдать»**: сначала сумма, затем выбор одного долга. У каждого долга есть список погашений/возвратов.
- Прежние поступления не удаляются и не переназначаются. Они доступны через **«Показать всю историю»** и остаются на счетах. У старых записей перепродаж нет цены покупки, поэтому они не попадают в новый расчёт чистой прибыли товаров.
- Фото уменьшаются на устройстве, голосовые заметки пишутся только по кнопке (до 90 секунд) и хранятся локально вместе с данными и резервной копией. Это аудиозапись, не автоматическая расшифровка.
- «Я должен» — обязательство; «Мне должны» — требование к возврату. Они показываются в разделе «Долги», но не вычитаются из общего капитала повторно.
- Все денежные суммы хранятся целыми копейками. Ввод — в рублях, с точкой или запятой.

Данные находятся в `%APPDATA%/Мой капитал/capital-data.json` (Windows сохраняет предыдущую запись в `.bak`). Не удаляйте эту папку при переустановке. Для переноса на другой ПК используйте **«Данные и настройки → Экспорт JSON»**. Импорт требует подтверждения замены. Браузерный предпросмотр использует отдельное локальное хранилище браузера.

## Обновления

1. При запуске и каждые 30 минут приложение проверяет последний стабильный выпуск GitHub. Кнопка в шапке позволяет проверить и установить обновление вручную.
2. При изменении интерфейса/логики скачиваются **только файлы с новыми SHA-256**. Неизменившиеся React, шрифты и другие файлы берутся из установленной версии или кеша. Файлы сжаты gzip. Полный пакет текущего интерфейса занимает около 164 КиБ; обычное изменение меньше.
3. Загрузка проверяется по контрольным суммам, распаковывается в отдельную папку и активируется только после полной проверки. При ошибке запуска возвращается встроенная рабочая версия. Финансовые данные лежат отдельно от кода.
4. Если изменилась оболочка Electron, используется `electron-updater`, NSIS и `.blockmap`: скачиваются изменённые блоки установщика. Для этого предыдущая карта блоков переносится в новый выпуск. Если кеш старой оболочки повреждён/удалён, возможен полный установщик — это штатный безопасный резервный путь, а не обязательная ручная переустановка.
5. Проверка обновлений не удаляет записи. Перед применением выполняется ожидание завершения сохранения.

После каждого изменения push запускает проверку и сборку новой версии Windows и Android. Выпуск публикуется только после проверок Windows и готовности подписанного APK той же версии; если Actions завершился ошибкой, обновление ещё не доступно. Правило выпуска для разработчиков закреплено в `AGENTS.md`.

Не удаляйте `update-manifest.json`, `update-*.gz`, `latest.yml` и `.blockmap` из выпусков: это служебные файлы апдейтера. Старые выпуски сохраняют карты блоков для дифференциальных обновлений.

## Синхронизация ПК и телефона

Данные остаются на обоих устройствах; это локальные копии, которые автоматически объединяются после сопряжения. Один раз на ПК откройте «Данные и настройки», а на телефоне в том же разделе выберите «Сканировать QR ПК». Выберите в настройках ПК адрес используемой сети, если показано несколько. Разрешите приложению доступ в частной сети Windows. Используйте только доверенную сеть: обмен по локальной сети не шифруется, QR содержит секретный ключ.

Когда приложение ПК запущено и устройства в одной сети, сохранённые изменения передаются автоматически в обе стороны, открытые страницы перерисовываются без перезагрузки. При обрыве связи данные остаются локально и обмен повторяется после восстановления; возможны задержки. Если ПК выключен или устройства в разных сетях, для обмена нужен заранее настроенный личный Supabase на обоих устройствах. Из-за ограничений связи и ОС нельзя гарантировать мгновенное обновление во время отсутствия сети или когда приложение остановлено. При одновременном изменении одной записи выигрывает более новая версия; несовместимые изменения откладываются, а не перезаписываются молча. Перед первоначальным объединением разных баз экспортируйте резервные копии с обоих устройств.

## Проверки и разработка

Требования: Node.js 22.12+, npm.

```bash
npm ci
npm test
npm run build
npm run dev
```

В отдельном терминале при запущенном dev-сервере:

```bash
npm run visual
```

Визуальная проверка охватывает все разделы, отдельные страницы перепродаж и шабашек, формы товара/продажи с фото и аудио, окно обновлений и ширины 1440/1280/1024/768/390. Тестовые суммы вводятся только в изолированный браузер и не попадают в приложение пользователя.

Сборка Windows:

```bash
npm run desktop:build
npm run release:verify
```

GitHub Actions `.github/workflows/windows.yml` собирает установщик, проверяет SHA-512/latest.yml/blockmap, затем на `windows-latest` устанавливает старую сборку и проверяет **оба** пути обновления на настоящем установленном приложении. Выпуск публикуется только после прохождения проверок. Отчёты и снимки экрана прикладываются к запуску Actions.

## Границы первой версии

Без облака, регистрации, банковской синхронизации и Android. Валюта — RUB. Это персональный учёт и сценарный расчёт, не бухгалтерская отчётность и не инвестиционная рекомендация.
