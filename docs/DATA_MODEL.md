# Модель данных и финансовые правила

## Хранение и доступ

Облачная таблица `public.ledger_entries` хранит пользовательские записи общего формата:
- `id` — UUID;
- `owner_id` — владелец из Supabase Auth;
- `kind` — `resale`, `job`, `consumerDebt`, `investor` или `category`;
- `payload` — поля предметной записи в JSONB;
- `created_at`, `updated_at` — временные метки.

RLS разрешает чтение и изменение только при `owner_id = auth.uid()`. Голосовые файлы лежат в закрытом Storage bucket `voice-notes`, в папке с UUID владельца; в payload хранится путь к файлу. Для браузерного локального режима записи находятся в localStorage и не синхронизируются.

Одна таблица делает первый этап гибким. При росте приложения таблицы можно нормализовать без изменения UI-домена.

## Деньги

Ввод и формат отображения — рубли; внутреннее представление — целые копейки. Отрицательные суммы не принимаются. Суммы не складываются с двоичной точностью JS float в рублях.

## Перепродажа

Запись хранит `purchaseKopecks`, `investmentKopecks`, статус продажи, `saleKopecks`, дату продажи, инвестора, процент и правило выплаты.
- Затраты = цена покупки + дополнительные вложения.
- Выручка = сумма продажи по проданным товарам.
- Прибыль/убыток = выручка товара − цена покупки − вложения. Для непроданного товара реализованный результат равен нулю.
- До продажи обязательство инвестору — возвращаемый капитал.
- После продажи к капиталу добавляется дополнительная выплата по выбранному договорному правилу; расчёт можно отметить завершённым.
- Правило выплаты на конкретное вложение выбирается из: процент от положительной прибыли, процент от суммы вложения, процент от выручки или ручная дополнительная сумма. Капитал не включается в эту дополнительную выплату.

Процентные правила нельзя считать юридическим/договорным заключением. Перед сохранением товара владелец выбирает вариант договора. Отдельный журнал частичных выплат инвесторам ещё не реализован.

## Подработка

- Для спила деревьев и собственных категорий указывается сумма записи.
- Для ремонта авто сумма работы — сумма строк списка `lines`.
- Доход от работ — сумма итогов работ; категория, адрес и время не меняют финансовый итог.
- Время окончания не может быть раньше времени начала; переход через полночь пока не поддержан.

## Потребительские долги

- Остаток = `max(0, начальная сумма − сумма зарегистрированных платежей)`.
- Платёж содержит сумму и дату; платёж больше текущего остатка блокируется.

## Главная сводка

За всё время отображаются отдельными показателями:
- Доход от подработки.
- Выручка перепродаж.
- Прибыль/убыток по завершённым продажам.
- Затраты на покупку и инвестиции.
- Непогашенные обязательства инвесторам.
- Остаток потребительских долгов.
- «Доход всего» = доход от подработки + результат перепродаж. Выручка повторно не прибавляется к прибыли.

Фильтр периодов — визуальная заготовка; изменение диапазона пока не подключено. При ошибке облачной записи приложение показывает уведомление, хранит локальную копию и очередь повторной отправки в localStorage. Очередь отправляется при следующем старте/обновлении; при неудаче запись остаётся в очереди.
